# Thor QA — 30 October 2026

Tested `c05c0362` and the fixes below on the USB AYN Thor (`c013eb4e`, Android 13), using the isolated application ID `app.foldcade.qa31`.

## Findings fixed

- **QA-01, P2 — Gboard consumes form navigation.** Open Settings › Library › RomM › Edit connection, press A on Server, then press Down on display 0 while Gboard's fullscreen editor is open. The text caret moves within Server and the form highlight stays there. Activity-level dispatch runs after the input method, so its existing vertical-key interception is too late. Commit `59230c83` intercepts keys before the soft keyboard on the connection form and delegates to the existing form dispatcher; the form owns both the press and the release, as the activity's own dispatch already does. Thor rechecks passed Down from Server to Client API token, Up from an edited token to Server, navigation to Save token, preservation of typed test text, and Back to the connection menu. The same form flow passed on the bottom display. The change covers the shared RomM/SteamGridDB form; SteamGridDB was not separately signed in. This is Android input-method integration, so the regression evidence is the real-device check rather than a JVM test that cannot reproduce Gboard.
- **QA-02, build blocker — language lint rejects the key dispatcher.** `:language:lintDebug` failed with three `RestrictedApi` errors on the `dispatchKeyEvent` override and super call. The public Activity callback is inherited through AndroidX core's restricted compatibility class. Commit `2c29e2d2` adds a suppression scoped to that override, with its reason. No dispatch behavior changed. Language lint now reports no issues.

No other behavior defect was confirmed during this pass. Intermittent black/static screenshots were traced to the Thor's own “Anti-image-retention pixel refresh in progress” overlay, not Foldcade rendering.
